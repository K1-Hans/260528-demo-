# 01 · AI 客服中台 — 深度规格（build-ready）

> 给「中台系统 demo 开发官」· 纯前端 mock，无后端 · 设计契约见 `../00-总规划-全景排序与选型.md` §3 与项目根 `DESIGN.md`（本文不复述，引用即可）
> 本 demo = 把 Hans 在维信金科主导的生产系统「维小豆智能客服 BOT + AI 客服运营系统」**产品化**。真实 KPI / 数据飞轮 / 多-agent pipeline 是它的灵魂，绝非通用客服后台。

---

## ① 一句话定位 + 行业锚定

**面向消费金融的「合规可审计 · 数据自驱」AI 客服中台**：多-agent pipeline（敏感词拦截 → 意图情绪 → 路由 QA/安抚 → 合规审核）把自助解决率从 70% 拉到 85%、转人工率砍到 14.77%、在线坐席 200→<30、月降人力约 200 万，且 AI 输出 100% 合规可审计。

- **行业锚定**：消费金融（产品锚 = 虚拟「维小豆 / 维小贷」借贷场景）。
- **海外对标**：Sierra（ARR $200M、outcome-based 按解决付费）、Decagon（hallucination detector）、Intercom Fin（平均解决率 67%）。差异点：本系统强制「合规审核 Agent + 全程可审计」前置，命中金融监管对幻觉零容忍 + EU AI Act 2026.08。
- **战略叙事点（埋进文案）**：Klarna 砍客服过猛后回招 → **hybrid（human-in-the-loop）才是终局**，所以本系统把「转人工」和「合规卡点」做成显式的一等公民，而非掩盖。

---

## ② 视觉签名 / point of view

**「暖呼吸 · 服务温度」**——客服是人与人的服务，用暖、克制、有手感的编辑式企业层表达。全 portfolio 唯一暖色系，刻意拉开冷调玻璃（车企）/ 作战室（风控/外呼/LLMOps）同类，确保各 demo 调性各有千秋。
（注：原「消金合规指挥感 / Command Graphite teal」于 2026-06-17 经 Hans 决策换向为本暖呼吸签名——根因是全线 demo 曾共用同一冷调底只换 accent，第一眼撞脸。）

- **Light 主（主场）**：Warm Ivory 暖象牙底（#FAF8F3），accent = **珊瑚陶土（coral #D97757；文字/描线用较深 #C85F3C 保证亮底可读）** 表示「健康/主操作」，辅以 **橄榄绿** 标在控、**琥珀** 标 badcase/拦截、**暖砖红** 标合规违规。Dark = Warm Charcoal 暖夜（暖棕墨 #1A1611，非冷石墨）+ 提亮珊瑚 #E0906F。
- **衬线标题**：页面/大标题走 Newsreader + Noto Serif SC 思源宋体（编辑人文感）；正文 / 数字 / UI 标签仍 Geist 无衬线保证清晰。
- **一页一 accent**：仪表盘走珊瑚，pipeline 调试页走琥珀，合规审计页走暖砖红，互不串色。
- 数字全 `tabular-nums`（KPI 是主角，必须对齐）；暖发丝线；卡片极轻描边 + 极柔投影，**扁平无玻璃 / 禁 AI 紫发光 / 禁霓虹 / 禁冷蓝绿科技感**。
- 气质参照：Anthropic 官网的暖象牙人文 + Notion/Linear 亮色编辑式克制 + 宋体标题的编辑温度。UI chrome 全 lucide 图标，**无 emoji**。

## ③ 角色 RBAC（4 角色 × 权限矩阵 + 登录页 + 角色切换）

沿用 `AuthContext` 模式，登录页 + 顶栏角色切换器（demo 期一键切）。

| 角色 | 仪表盘 | 实时对话台 | 知识库 CRUD | Badcase/质量运营 | Pipeline测试 | 合规审计 | LLM/Prompt配置 | RBAC管理 |
|---|---|---|---|---|---|---|---|---|
| **运营总监** Admin | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| **知识运营** | ✓ | 只读 | ✓ | ✓ | ✓ | 只读 | — | — |
| **合规专员** | ✓ | 只读 | 只读 | ✓(标注) | — | ✓ | — | — |
| **质检/坐席班长** | ✓ | ✓(可接管) | — | ✓ | — | 只读 | — | — |

- 无权页面走 `EmptyState`（"无权限，请联系运营总监"），不是 404。
- 角色切换实时改导航可见项 + 操作按钮 disabled 态，体现真实分权。

## ⑤ 核心模块详述（职责 + 关键交互 + mock 数据轮廓 + ECharts）

> 复用车企中台 `src/components/ui.tsx`：StatCard(count-up) / TrendChip / Sparkline / DataTable / CommandPalette / Segmented。新增「对话/转写时间轴」「Pipeline 阶段条」组件（质检/外呼 demo 可复用，见 00 文档 §5）。

### A. 实时对话台 `/live` — 多-agent pipeline 可视化（核心差异点）

- **职责**：左栏会话流列表（虚拟客户进件）；中栏对话气泡时间轴；右栏 **Pipeline 阶段条**——每条客户消息逐级点亮：`敏感词拦截(A1) → 意图/情绪(A2) → 路由(soothe/hybrid/qa) → RAG检索(A3) → LLM生成 → 合规审核(A4)`，每阶段显示耗时(ms)、命中标签、置信度，可点开看细节（如 A2 输出 `{intent_l1/l2/l3, emotion, route}`，A3 显示 Top-5 召回 QA + 余弦相似度，≥0.88 标「高置信直通」）。
- **关键交互**：A4 合规审核若拦截 → 气泡变琥珀 + 显示拦截原因（违规承诺/利率虚假宣传/催收红线/PII 泄漏）+ 「转人工」按钮高亮（体现 human-in-loop 卡点）；班长角色可「接管」。
- **mock 数据**：6–8 条进行中会话，意图覆盖「还款失败/提前结清/利率咨询/投诉/账单分期/注销」；情绪含「焦虑/愤怒/中性」；含 1 条敏感词命中（扬言投诉监管）走安抚路径的样例。
- **ECharts ①**：右下角实时「pipeline 各阶段平均耗时」横向柱（圆角、青色渐变）。

### B. Badcase 运营 `/badcase` + 拒识 `/reject` — 数据飞轮闭环

- **职责**：badcase 列表（命中错答/答非所问/用户追问），状态机 `待处理 → QA已修 → 已回灌知识库`；拒识 = 无召回/低置信的知识缺口，可一键「转草拟 QA」。体现真实飞轮：**badcase→QA→反哺知识库**。
- **关键交互**：选 badcase → 右侧抽屉显示原对话 + 召回详情 + 「生成修复 QA」（mock 自动填 q/a 草稿）→ 提交后该条进「待发布」(见状态机)。
- **ECharts ②**：飞轮闭环 Sankey/桑基或环形——「脱敏会话 → 自动生成测试用例 → badcase 沉淀 → QA 修复 → 知识库扩容」流量；标注 QA 库 **300 → 2万** 的增长。

### C. 合规审计中心 `/audit` — 100% 可审计

- **职责**：所有 AI 输出的合规审计流水（不可篡改感的表格），列：会话ID/客户消息/AI回复/A4判定(通过/拦截/改写)/触发规则/审核Agent置信度/时间戳。**100% 输出留痕**是卖点。
- **关键交互**：按「拦截类型」筛选；导出审计报告（mock 下载提示）。
- **ECharts ③**：合规通过率趋势线（目标线 100% 参考线）+ 拦截类型分布饼/玫瑰图。

### D. 知识库分层 `/kb/*` — 6 库 + 双维状态机

- **QA 库**：`DataTable`（可排序/筛选/空态/skeleton），列：q/a/意图标签/状态/向量化状态/命中次数/更新人。**双维状态机**（00 引真实系统）：业务态(已生效/待发布/已下线) × 技术态(已向量化/未向量化)正交，用两枚 Badge 表示；编辑 q 自动 demote 到「待发布」给提示 toast。
- **敏感词库**：主词 + 变体映射表（"还.款" 变体回归主词）+ 11 类风险标签。
- **回收站**：软删除列表，可「恢复(→待发布)」或「物理删除」。
- **ECharts ④**：知识库分层条形（QA 2万/卡片530/寒暄1400/转人工150 各库条数）+ 近 30 天增长面积图。

### E. 智能体管理 `/agents` + Pipeline测试 `/pipeline-test`

- **职责**：`/agents` = pipeline 编排只读画布（A1–A4 节点 + 各挂的模型/规则）；`/pipeline-test` = 选用例集跑回归，显示通过/回归失败、对比新旧 Prompt 版本（A/B）。体现「脱敏会话自动生成测试用例」。
- **ECharts ⑤**：A/B 两版意图识别准确率 / 解决率对比分组柱。

### F. LLM 配置 `/llm` + Prompt 版本 `/prompt` + 意图分类 `/intent`

- **职责**：`/llm` = 各 pipeline 节点分别配模型（意图节点=Gemma 小参 MoE、QA 节点=Qwen3 27B FP8 量化、Embedding=text-embedding-v3 1024维），含「本地/云端」「成本/延迟」标签——呼应「本地模型逐节点定模」的私有化卖点。`/prompt` = 版本树 + diff + 回滚。`/intent` = 三级意图树（可折叠）。
- **ECharts ⑥**：各节点模型「成本×延迟」气泡散点（X=延迟 Y=单价 size=调用量）。

### G. 会话日志 `/logs`

- 全量会话检索（关键词/意图/情绪/路由/是否转人工），点开复用对话时间轴组件。

## ⑦ 差异化 + 反 slop 要点

**差异化（vs 通用客服后台）**：
- ✅ **多-agent pipeline 可视化** + 合规审核前置（A4 幻觉拦截）——通用后台只有「对话+知识库」，没有四级流水可视。
- ✅ **数据飞轮闭环**做成显式模块 + 动画（badcase→QA→反哺，300→2万）——这是 80% 同行没做透的。
- ✅ **真实 KPI 全超额** + 目标参考线，不是占位数字。
- ✅ **逐节点多模型 + 本地化**（Gemma MoE / Qwen3 FP8）——私有化金融硬通货。
- ✅ **human-in-loop 卡点显式化**（转人工 + 合规拦截高亮）——呼应 Klarna 回招教训。

**反 slop 红线（ship 前逐条过，见 §3）**：无 AI 紫/霓虹/玻璃涂满；数字全 tabular-nums；用消金真实场景文案（"还款失败/提前结清/利率咨询"），**禁 lorem ipsum / 禁"赋能/无缝/一站式"**；一页一 accent；4px 网格；图表全 ECharts，**禁假 div 进度条**；Dark+Light 双主题；桌面+移动两档可看。

## ⑧ 5 分钟演示流

1. **(0:00) 登录 → 运营总览**：KPI count-up 跳到 85.23% / 转人工 14.77%；6 月趋势线 draw-in 越过目标线；右下飞轮动画起转。一句话："这是把维信金科生产系统产品化——半年 200 坐席降到 30 以内。"
2. **(1:00) 实时对话台**：点一条「还款失败」会话 → 右栏 pipeline 逐级点亮（A1 无敏感词 → A2 意图=还款/情绪=焦虑 → 路由 qa → A3 召回 Top-5 命中 0.91 高置信直通 → A4 合规通过）。再点一条「扬言投诉监管」→ A1 命中敏感词 → 走安抚 Agent → A4 拦截一句违规承诺 → 转人工高亮。
3. **(2:30) Badcase 闭环**：选一条 badcase → 抽屉「生成修复 QA」→ 提交进「待发布」→ 回飞轮图看 QA 库 +1。讲数据飞轮。
4. **(3:30) 合规审计中心**：展示 100% 留痕流水 + 通过率 100% 参考线 + 拦截类型分布。讲「金融监管零幻觉容忍 + EU AI Act」。
5. **(4:30) LLM 配置 + RBAC 切换**：展示逐节点本地模型（Gemma/Qwen3 FP8）；切到「合规专员」角色，导航与按钮即时收敛。收尾对标 Sierra/Intercom。
